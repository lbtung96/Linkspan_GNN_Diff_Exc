# CLAUDE.md

Guidance for Claude Code working in this repository.

This is the **consolidated** pipeline. The development history — abandoned
architectures, superseded results, the audit that corrected them — lives in
`Linkspan_GNN_FineTuning/`, whose `CLAUDE.md` is preserved here as
`docs/CLAUDE_source_repo.md`. Read that only for archaeology. This file is
authoritative for anything you actually run.

Start with [README.md](README.md) for orientation and
[PROVENANCE.md](PROVENANCE.md) for what reproduces and how faithfully.

## The paper's results live in `Final_results_for_paper/` (since 2026-09-26)

Every number the paper reports is rebuilt there, on **one population with one
protocol**: 5500 structures (1375 per girder count, seed 20260507, Ng ≥ 3 spacing
up to 3000 mm, selected-mode MAC ≥ 0.85), a fixed 500-structure test set, a
balanced and nested sweep N = 100–5000, **N = 2000 as the main network**
(the smallest N at which every mode reaches test MAC ≥ 0.9; it was N = 600
until 2026-09-28; the ablation stays an equal-N comparison at 600),
broadband only, 5000 epochs, seed 123, **one seed**, **best-validation
checkpoint everywhere**, full nested fine-tuning only. Read its
[README](Final_results_for_paper/README.md) before touching it; the numbers are
in `Final_results_for_paper/pipeline/results/PAPER_RESULTS.md`, generated by
`s9_report.py`. PROVENANCE Phase K records why (the generation audit) and what
moved.

- The root `PAPER_RESULTS_OLD.md` (named `PAPER_RESULTS.md` until 2026-09-29;
  `tools/make_paper_results.py` writes it) and `experiments/E1`–`E14` describe
  the previous populations. They stay reproducible and in the regression
  contract, but they are history for the paper — never quote them beside the
  new numbers.
- **The ablation (§3) is a full grid since 2026-09-29**: GraphSAGE / EdgeGATConv
  × no edge features / edge orientation (cos, sin) / 800-d complex coherency,
  all at N = 600 (`fr_common.ABLATION_GRID`). Four of its edge-feature modes do
  not exist in the library modules; `pipeline/fr_edge_modes.py` patches them in
  memory (as `s0` patches the generator) — keep the library files unmodified.
  Read §3 before writing about it: EdgeGATConv beats GraphSAGE **only** with the
  coherency, GraphSAGE **does** use phase, and both orientation arms sign
  torsion without any phase input (E12's asymmetry). Never write that signed
  torsion needs phase-carrying edges, or that EdgeGATConv wins at every input.
- **Select sweep networks by run name** (`edgegat_N{N}`), never by
  `arch == "edgegat"`: the ablation's EdgeGATConv arms are `edgegat` at N = 600
  too, and once leaked into the sweep table and figures.
- **Training times recorded in `run_summary.json` are not comparable** across
  runs: they shared the machine with one to six others. `s11_ablation_cost.py`
  times each ablation arm alone; its timing columns are machine noise, so a
  re-run shows DIFFERS there and only there.
- `s10_figures.py` draws fig4/7/8/10/11 with the previous paper's own modules in
  `experiments/E2_training_distribution/figures/` (`figstyle`, `plot_loss_curves`,
  `plot_synthetic_performance`, `plot_representative_modeshapes`) — the author
  wants that style. Renaming or changing their functions breaks those figures.
- The conventions below that name 500 epochs, five seeds, last-epoch test metrics
  or `population_dataset_modes4/` are the rules for `experiments/`, not for
  `Final_results_for_paper/`.
- Its stage scripts sit in `pipeline/`, apart from `data/` and `runs/`, because
  `tools/run_stage.py` hashes every result file under a stage's own folder.
- **Thread count is part of bit-reproducibility on CPU.** Training uses 2
  threads per process; zero-shot and fine-tuning torch's default (as E2 did).
  Across thread counts, fine-tuning differs by up to 9e-05 and inference in the
  last float32 bit.
- **The GPU does not help this model.** Measured: one 2-thread CPU process runs
  an epoch as fast as the RTX A1000 (1.2 s at N = 600), and more threads are
  slower. Throughput comes from running processes side by side.

## Hard rules

1. **Run everything from the repository root.** Data paths resolve against the
   working directory, not `__file__` (`OUT_DIR = Path("population_dataset_modes4")`,
   `REF_DIR = Path(".")`, `GRAPH_ROOT = Path("phase3_real_graphs")`). Use
   `python tools/run_stage.py <script> [args]`, which sets the CWD and records
   the run.

2. **CPU torch only.** `GraphSAGE_Modal_GNN.py:74` selects `cuda:0` whenever
   CUDA is visible. `run_all.py` refuses to start if `torch.cuda.is_available()`,
   so everything trained, inferred or fine-tuned *here* is CPU. Not everything
   *published* is: the 34 E3 sweep runs were trained on `cuda:0` in the source
   repository (their `run_summary.json` says so; `config.json` has no device
   field) and are copied, not retrained. §6 and §6.1 rest on them. §7.5's
   broadband controls did too, through `edgegat_20260507_123555`, until the
   2026-09-14 switch to 500 epochs retired that checkpoint. Never write "every
   published number is a CPU number".

3. **Library modules stay flat at the root, with their current filenames.**
   Every internal import is `from <module> import ...` with no package. The 14
   below are a closed set — removing any one breaks the others. In particular
   `GraphSAGE_Modal_GNN.py` is not "the old architecture": `EdgeGATConv_Modal_GNN.py`
   imports 25 symbols from it, 11 of them private.

   ```
   grid_modal_Kinematic_MPC     standalone_mode_matching_mmi   export_projected_graph
   simulate_uniform_inertial_u3_white_noise    generate_population_dataset_modes4
   GraphSAGE_Modal_GNN          EdgeGATConv_Modal_GNN          phase3_utils
   infer_phase1_unseen_structure               infer_phase2a_unseen_structure
   infer_phase2a_unseen_structure_edgegat      infer_phase2a_deterministic_edgegat
   build_phase3_graphs          analyze_phase1_run
   ```

4. **Never reformat these two lines** in `generate_population_dataset_modes4.py`:

   ```python
   OUT_DIR = Path("population_dataset_modes4")
   N_STRUCTURES_TOTAL = 800
   ```

   `E2/stage0_generate_narrowband.py` and `E3/generate_sensitivity_dataset.py`
   locate them by exact string match and hard-fail if they change. They patch a
   temporary copy to redirect `OUT_DIR` into a sandbox, because
   `main(bandpass=False)` calls `clean_output_directory(OUT_DIR)`, which would
   wipe the production tree.

5. **Never run `generate_population_dataset_modes4.py` in narrowband mode
   directly.** Use `E2/stage0_generate_narrowband.py`, which is the safe wrapper.
   Its interactive inspect prompt is now guarded by `sys.stdin.isatty()`: the
   original `except EOFError` only catches a *closed* stdin, so under a detached
   run - where stdin is an open pipe that never delivers a line - `input()`
   blocked for ever after all the work was done. That hung a 16-hour background
   run. Keep the guard. The guard is not enough on its own: a shell can hand the
   child a console stdin, so `isatty()` passes, and `main()` also ends in
   `plt.show()`, which blocks on open windows with an interactive backend. A
   wrapper must select the Agg backend before importing the generator and give
   it an empty non-TTY stdin — `Final_results_for_paper/pipeline/s0_generate_population.py`
   does both.

6. **Stage scripts find the root by counting parents.** `experiments/E*/stage*.py`
   uses `parent.parent.parent`; `experiments/E2_training_distribution/figures/*.py`
   uses `PARENT.parent.parent`; `Final_results_for_paper/pipeline/*.py` goes
   through `fr_common.REPO` (two parents up). Moving a stage to a different
   nesting depth means re-counting that walk.

7. **Close out any work that produces numbers.** See *Closing out a change*
   below — this is not optional and does not need asking about.

## Closing out a change

**Trigger.** Any of these, without being asked:

- a stage was re-run, or its script edited
- a hyperparameter, protocol, seed, or structure set changed
- an experiment was added, and any time an investigation reaches a conclusion
- a checkpoint, dataset, or label was rebuilt

Editing only prose, plotting code, or tooling does **not** trigger it.

**Do this, in order:**

```bash
python tools/run_stage.py <stage> [args]        # 1. never bare-run a stage
python tools/diff_against_reference.py --atol 1e-5   # 2. what moved, and by how much
python tools/snapshot_baseline.py --apply       # 3. only once (2) is understood
python tools/make_results_summary.py            # 4. regenerate results/RESULTS.md
python verify_reproduction.py                   # 5. must stay 12/12
```

Then, in the same turn:

- **Say which numbers moved and by how much.** A stage that changed a headline
  figure and a stage that reproduced its output exactly are different events and
  must not be reported the same way.
- **Update `PROVENANCE.md`** if the change alters what reproduces, what is
  pinned, or what cannot be regenerated.
- **Commit**, with the numbers in the message.

**Order matters.** Step 3 moves the regression target, so running it before
step 2 destroys the comparison that tells you whether the change was intended —
you would be overwriting the baseline with the very output you were meant to
check against it.

**Never hand-edit a results table.** `results/RESULTS.md` is generated from the
CSVs by step 4. Transcription is precisely how the source repository came to
publish `ssi_summary.ssi_mac_vs_fe_target` — a quantity the network takes no part
in — as a GNN result, in 32 cells of a table, uncaught for months.

**If a number moved and you did not intend it, stop and say so** rather than
snapshotting it into the baseline. An unexplained movement is a finding.

## Fixed conventions

- **Modal targets**, always in this order: `["B1", "T1", "B2", "T2"]`
- **Node features** `x_psd` — Welch PSD, `(N, 400)`, **row-normalised by max-abs**
- **Edge features** `edge_attr_cpsd_full` — complex coherency
  `Pxy / sqrt(Re(Pxx)·Re(Pyy))`, interleaved `Re(f0), Im(f0), Re(f1), Im(f1), ...`,
  `(E, 800)`
- **Welch**: Hamming, `nperseg=2048`, `noverlap=1024`, `nfft=2048`, `detrend=False`,
  one-sided, `scaling='density'`, first 400 bins
- **Real recordings are 128 Hz**, the synthetic pipeline is 200 Hz. Real spectra
  are **interpolated onto the 400-bin training grid** (Δf = 0.09765625 Hz,
  0–38.96 Hz). Truncating instead would compress the frequency axis by 1.5625×.
- **Bandpass** 1.5–20 Hz, 4th-order Butterworth, zero-phase, from
  `phase3_utils.BANDPASS_F_LOW/HIGH`
- **Checkpoint compatibility**: node feat dim 400, edge feat dim 800

Those first three are not stylistic. Getting any of them wrong is what caused
the 2026-08-21 failure, in which the network returned its zero-input response
for every real structure and nobody noticed for months. `E5/stage1_feature_stats.py`
and `E5/stage3_zeroshot_corrected.py` (which `E5/stage6_e2_decomposition.py` runs
per seed) both gate on it — **do not skip them.**

## SSI labels

`SSI_modal_infor/mode_selection.json` is the authoritative mode selection,
curated from `COMAC_PBSHM/COMACPBSHM_Rev01.m`. It replaced a frequency-blind
argmax-MAC matcher that was wrong at **11 of 36 mode slots**.

`_mac_match_ssi_modes` still exists in `infer_phase2a_deterministic_edgegat.py`
as a fallback for files that are not pre-ordered. A `.mat` carrying exactly 4
modes **and** a `mode_names` variable equal to `["B1","T1","B2","T2"]` takes the
identity path instead. Shrinking a file to 4 modes is *not* enough on its own:
argmax has no uniqueness constraint. Against the FE targets of 2026-08-26 it
permuted Hellesylt and Leknes (FE T2 scored higher against curated T1). Since the
2026-09-18 T2 override it happens to return the identity at all nine structures,
which is luck, not a guarantee — keep the identity path.

SSI is used **only as evaluation labels and fine-tuning targets**, never to build
input features. Using SSI to isolate modal content in the features would make the
whole exercise circular.

## Things that are easy to get wrong

- **Test metrics everywhere are last-epoch, not best-validation.**
  `evaluate_test_set` runs on the in-memory model after the final epoch;
  `best_model.pt` is saved but never reloaded for test. The convention is uniform
  so comparisons hold, but it must be declared in any write-up.
- **Everything under `experiments/` trains for 500 epochs, since 2026-09-14**
  (`Final_results_for_paper/` trains for 5000 and scores best-validation). E2 checkpoints live in
  `experiments/E2_training_distribution/runs_ep500/` (the 100-epoch runs stay in
  `runs/`), and ablation arms in `E1/runs/*_e500` (beside `*_e100`). There is no
  learning-rate schedule and no early stopping, so a 500-epoch run *is* its
  100-epoch run continued, bit for bit. That is what makes
  `experiments/E11_epoch500/` a clean comparison. Choose the budget by validation
  loss, never by real-structure numbers: several of those are *lower* at 500.
- **The epoch axis of the E3 sensitivity grid is degenerate under
  `best_model.pt`, and only there.** A longer run continues the same
  trajectory, so where the best epoch falls below 500 the 500/1000/2000-epoch
  runs select *identical weights* — true for 7 of 8 N values. The synthetic
  numbers are last-epoch and do compare training lengths; for transfer, use
  `last_model.pt`.
- **`800_Samples_Ng2Split` and `edgegat_20260507_123555` are retired 100-epoch
  checkpoints.** The first's dataset is gone and predates the `Ng < 3` guard fix.
  The paper's §7.3–7.5 now runs on the E2 checkpoints, five seeds, via
  `E5/stage6_e2_decomposition.py`. `E5/stage3`, `E5/stage4` and `E6/task2` on the
  legacy checkpoint remain only as history. Never use either as a baseline for a
  new comparison.
- **The synthetic excitation is not uniform u3 base shaking**, despite the
  module name `simulate_uniform_inertial_u3_white_noise.py`.
  `build_influence_matrix` gives every support-node DOF (x, y, z) its own
  independent white-noise record, so torsion is excited even on a
  mirror-symmetric deck.
- **Phase-blind does not mean sign-blind here — read
  `experiments/E12_phase_blind_sign/REPORT.md`.** At 500 epochs the ablation's
  node-PSD-only arm reaches T1 0.52. That excitation leaves a left/right
  asymmetry in the node spectra even on mirror-symmetric decks, and MAC ignores
  the global sign, so a network only has to tell the deck's halves apart.
  Retrained without the asymmetry it falls to 0.008; with the graph but flat
  spectra, to 0.002. EdgeGAT keeps 0.898 and 0.927 under the same two controls, because its sign comes through
  the edges. Never write that phase-blind features make signed torsion
  impossible. The 2026-09-29 ablation grid in `Final_results_for_paper/` shows the
  same on the new population: both edge-orientation arms (no phase input) reach
  T1 ≈ 0.7.
- **LOOCV comes in two protocols.** `legacy` selects the model on the structure
  it then scores. Measured here over 9 structures × 5 seeds at 500 epochs, that
  inflates the result by **+0.041 to +0.077 MAC** depending on configuration
  (largest for full/broadband; +0.043 to +0.106 at 100 epochs). `nested` holds
  out a separate rotating validation structure. **Quote `nested`** — see
  `results/RESULTS.md`.
- **Torsion does not transfer, and we know why — read
  [docs/TORSION_TRANSFER_FINDING.md](docs/TORSION_TRANSFER_FINDING.md) before
  re-opening it.** The cross-deck anti-phase cue is present in the recordings
  (`Re γ` −0.785 at T1) and reaches the network inverted (+0.584). Two separable
  causes: **0 of 70** transverse sensor pairs are joined by any graph edge, and
  50 propagation iterations average the sign away. Most intuitive fixes are
  already ruled out by measurement, and inference-time repair without retraining
  makes torsion *worse*. That file carries the provenance for every number.
- **Never mix units of replication.** The narrowband-vs-broadband zero-shot
  difference tested p = 0.015 with the seed as the unit and p = 0.26 with the
  structure as the unit, at identical effect size (8 structures, 100 epochs); at
  9 structures and 500 epochs it is p = 0.086 against 0.26. Seed answers "will retraining reproduce
  this?"; structure answers "will it hold on a new bridge?". A table that pairs
  one unit with some rows and the other with the rest manufactures a false
  contrast. E7 reproduced the same trap exactly: the 15-vs-30-mode T1 difference
  tests p = 0.049 by seed and p = 0.27 by structure, at an identical −0.040 MAC.
- **The broadband-beats-narrowband claim is "mean margin, majority of seeds",
  not "every seed".** The stricter form held only until the 2026-09-03 geometry
  rebuild, and it was never robust: seed 124's margin was +0.0009, so one
  coin-flip seed carried it. The rebuild moved that seed to −0.0097 while the mean
  margin barely changed, +0.0513 → +0.0480. At 500 epochs broadband wins 5 of 5
  seeds on a mean margin of +0.0378, but two of those margins are +0.0005 and
  +0.0014, so the every-seed form is still a coin flip. Quote the **mean margin**;
  the gate in `verify_reproduction.py` asserts that plus a strict majority.
- **Report frequency error against both SSI and the FE target.** A systematic
  +2.19 / +2.07 Hz mean SSI-above-FE offset survives at B2/T2 (9 structures,
  `E2/stage5_ssi_vs_fe.md`) and is genuine FE softness, not a labelling
  artefact. Treating SSI as ground truth makes the frequency head look worse
  than it is. At T2 it is not uniform: the two overridden slots (below) sit
  *below* FE, by −3.69 Hz at Hellesylt and −2.74 Hz at Leknes.
- **`REAL_STRUCTURE_PARAMS` and `build_phase3_graphs.STRUCTURES` are kept in
  sync.** They were reconciled on 2026-09-02 and now agree field for field on all
  12 structures. `build_phase3_graphs.STRUCTURES` stays canonical for geometry.
  Edit one, edit the other in the same commit — `E5/stage0_checks.py` diffs them,
  but only after the fact.
- **`mode_col_swap` and `mode_candidate_override` are deliberately NOT in the
  geometry dict** — they are mode-matching corrections, not geometry — so
  anything building FE params from `build_phase3_graphs.STRUCTURES` must carry
  both across from `REAL_STRUCTURE_PARAMS` explicitly. `build_phase3_real_dataset.py`
  once did not carry the swap, and `assemble_deterministic_phase2a_payload`
  silently popped `None`. It went unnoticed while Leknes B2/T2 sat 206 mHz apart;
  under the 2026-09-02 geometry the gap is 891 mHz and the unswapped order scored
  **B2 MAC 0.005** against SSI (swapped: 0.925). **Both are label-only:** they
  change which FE mode a slot is *scored against*, never which modes are
  *simulated* as network input — that stays the matcher's selection, as the
  training generator would produce it. `E6/task2_propagation_only_control.py`
  drops both on purpose for that reason. Letting the override change the
  simulated set was tried and rejected (2026-09-18): the network had never seen
  that mode set, and its FE-simulated ceiling at Hellesylt fell in every mode
  (B1 0.870 → 0.367).
- **Two FE targets are overridden, since 2026-09-18: Hellesylt T2 → FE
  candidate #7 (13.14 Hz), Leknes T2 → #6 (12.71 Hz).** The matcher's T2 twists
  the whole deck one way; the measured T2 reverses its twist just past the
  support. Table 8 moves 0.093 → 0.876 and 0.011 → 0.412 (T2 mean 0.588 → 0.720).
  They were chosen by **one rule applied to all 36 cells** — the best FE mode
  within 0.5–2× the SSI frequency, adopted if it beats the matcher by ≥ 0.05 —
  which changes exactly these two. Because the rule selects by MAC against SSI,
  those two cells are maximised quantities: **state the rule wherever Table 8
  appears.** Each override is declared with its frequency and fails loudly if a
  geometry change shifts the candidate numbering. Evidence and the 36-cell scan:
  `experiments/E2_training_distribution/t2_mac_diagnostic/`. Leknes's 0.412 is
  still weak and no FE mode up to 40 does better — do not describe it as fixed.

## Verification

```bash
python verify_reproduction.py                           # four gates; must be 12/12
python tools/check_paths_resolve.py                     # path constants resolve
python tools/run_stage.py <script> [args]               # run + log + ledger
python tools/diff_against_reference.py --atol 1e-5      # vs results/baseline/
python run_all.py --list                                # the whole plan
```

`--atol 1e-5` is the right tolerance for stages that re-run the FE model:
`eigsh` is called with no fixed start vector, so ARPACK picks its own, and the
worst deviation measured anywhere is 7.8e-07. It is also the tolerance
`stage0b_verify_pairing.py` already applies to the same path. Stages that only
run inference over stored features are bit-reproducible — check those at
`--atol 0`.

**Two baselines, and they answer different questions.**
`results/baseline/` is what *this* repository computes (9 structures) and is the
ongoing regression target — `--against baseline` is the default.
`results/reference/` is the 8-structure state **as inherited**, used once to
prove the migration was faithful; that question is settled in
`results/GATE1_MIGRATION_REPORT.md`. Do not regenerate `reference/`. Move
`baseline/` only via `tools/snapshot_baseline.py --apply`, and only after you
have read the diff.
